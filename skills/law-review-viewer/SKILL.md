# 법률 검토 뷰어

검토 내용을 JSON 하나로 적고, 템플릿에 넣어 **오프라인 단일 HTML**을 만든다.
화면 코드에는 사건 내용이 없다. 다음 검토 때는 JSON만 새로 쓴다.

## 만들어지는 화면

1. **요약** — 결론 한 줄(검은 띠) → 숫자 카드 4개 → 항목 카드 목록
2. **상세** — 항목을 누르면 `법률 → 시행령·규칙 → 처분기준 → 예외·겹침` 4단계가 세로로 펼쳐진다. 단계마다 쉬운 말 한 줄 + 조문 원문(핵심 문구 형광) + 넘어가는 이유
3. **표** — 엑셀처럼 정리된 한 장. `TSV 복사`로 한글·엑셀에 붙는다
4. **보고서 모드** — 버튼을 숨기고 캡처 영역(800px)에 점선을 띄운다
5. 인쇄(요약은 A4 세로, 표는 A4 가로), 평문 복사, 다른 JSON 불러오기

## 작업 순서

### 1. 범위를 먼저 확정한다
검토 항목(쟁점) 목록과 **기준 시점**을 정한다. 행정처분이면 위반행위일이 기준이다.
항목은 처분 대상(기사/회사/시 등)과 종류(과태료/과징금/명령 등)로 나눈다.
권한·절차도 항목 하나로 넣는다. 보고받는 사람이 반드시 묻는다.

### 2. 조문 원문을 확보한다
`reference/law-sourcing.md`를 그대로 따른다. 특히:
- `mcp__law__law_body`는 **시행예정본을 줄 수 있다**. `기본정보.시행일자`와 `조문시행일자`를 먼저 본다.
- 조문 본문은 국가법령정보센터 **XML**에서 가져온다. PDF에서 줄을 이으면 띄어쓰기가 사라진다.
- 별표는 표로 손수 옮기고, PDF를 그림으로 렌더해 금액을 눈으로 대조한다.

### 3. JSON을 쓴다
`reference/data-schema.md`의 구조를 따른다. 파일은 scratchpad에 `data.json`으로 둔다.

쓰는 요령:
- `gist`는 **호·목 같은 법령 용어 없이** 쉬운 말 한 문장. "별표 6 버목 2)에 해당" (X) → "명단에 없는 준수사항이라 10만원" (O)
- `arrow`는 앞 단계에서 이 단계로 **넘어가는 이유**. 이게 있어야 사슬이 읽힌다.
- 결론이 사실관계에 달려 있으면 `certainty`를 `조건부`로 두고 `conds`에 확인할 사실을 적는다. 확정으로 적어 놓고 단서에만 조건을 적으면 보고 때 지적받는다.
- 다른 항목에 흡수되거나 부과하지 않는 항목은 `sum: false`. 화면에 `합산 제외`로 표시되고 합계에서 빠진다.
- 근거가 두 갈래면 **둘 다 싣는다**. 같은 결론에 이르면 그 자체가 논거가 된다.

### 4. 만든다
```bash
python "<이 스킬 폴더>/assets/build.py" data.json "<저장할 경로>.html"
```
`<이 스킬 폴더>`는 이 SKILL.md가 있는 폴더다. 플러그인으로 설치했으면 `${CLAUDE_PLUGIN_ROOT}/skills/law-review-viewer`, 스킬만 복사해 쓰면 `~/.claude/skills/law-review-viewer`다.
build.py가 먼저 검증한다 — 없는 law/party/kind id, 표의 칸 수 불일치, 본문에 없는 형광 문구, 빠진 필수 항목. 오류가 있으면 HTML을 만들지 않는다.

### 5. 눈으로 확인한다
헤드리스 엣지로 찍어서 **직접 본다**. 표가 찌그러지거나 글자가 겹치는 일이 자주 생긴다.
```bash
"C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless=new --disable-gpu \
  --hide-scrollbars --window-size=1000,2600 --screenshot="qa.png" "file:///<경로>"
```
상세·표 화면은 파일을 복사해 `render();` 앞에 `S.view='detail';S.issue='i1';` 또는 `S.view='table';`를 넣어 찍는다.
인쇄는 `--print-to-pdf`로 확인한다.

### 6. 스스로 검수한다
`reference/law-sourcing.md` 끝의 점검표를 돌린다. 특히:
- 처분기준이 사업정지가 아닌데 과징금으로 갈음하고 있지 않은가
- 금액 합계와 표 하단 합계가 맞는가
- 인용한 조문이 기준일에 시행 중이었나

## 화면 규칙 (손대지 말 것)

- 콘텐츠 폭 **800px 고정**(max-width 아님). 이 폭이어야 캡처해서 한글 A4 본문에 붙였을 때 10pt로 읽힌다.
- 흰 카드 + 회색 배경 + 그림자 없음. 색은 결론 숫자에만.
- 글자 굵기는 400/700만. 맑은 고딕에 500·600이 없어 전부 굵어진다.
- 외부 CDN·웹폰트 금지, `fetch` 금지, `<script type="module">` 금지. file://에서 전부 막힌다.
- 조문은 **이미지가 아니라 텍스트**로 싣는다. 검색·복사가 되어야 한다.

템플릿을 고쳐야 할 일이 생기면 `assets/viewer_template.html`을 고치고, 고친 뒤 반드시 `node --check`로 스크립트를 확인한다(`<script>` 안쪽만 떼어 검사).

## 산출물 두는 곳

검토 대상 자료가 있는 폴더에 `<검토명>.html`로 둔다. 데이터 JSON도 같이 두면 다음에 고쳐 쓰기 쉽다.
파일을 옮기거나 이름을 바꾸면 브라우저에 저장된 화면 상태는 사라진다(내용은 파일 안에 있으므로 무관).
